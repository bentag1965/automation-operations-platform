# Contributing

Contributions, suggestions, and issue reports are welcome.

## Ground Rules

- Keep examples generic and portfolio-safe.
- Do not submit employer-specific code, customer data, credentials, API keys, private network details, or proprietary configuration.
- Prefer small, focused changes with a clear explanation of the problem being solved.
- Add or update tests when behavior changes.
- Keep documentation aligned with the implementation.

## Pull Requests

A useful pull request should include:

1. what changed
2. why it changed
3. how it was tested
4. any operational or security implications

## Security

Do not publish real secrets or sensitive third-party data in issues, commits, pull requests, fixtures, or screenshots.
